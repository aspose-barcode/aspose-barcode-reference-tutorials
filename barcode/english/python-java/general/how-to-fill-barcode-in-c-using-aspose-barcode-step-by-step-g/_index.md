# How to fill barcode in C# using Aspose.BarCode

If you need to **how to fill barcode** in a .NET application, this tutorial shows the complete process. You will generate a postal Planet barcode with solid bars, then create an empty‑bar version of the same barcode, all with a single line‑of‑code change.

The guide covers everything you need to know: project setup, X‑dimension tuning, switching between filled and empty bars, and how to verify the generated PNG files. No external documentation is required—just copy the code, run it, and you’ll see the result.

## Prerequisites

Before you start, make sure you have:

* .NET 6.0 SDK or later installed  
* A development environment such as Visual Studio 2022 or VS Code  
* The **Aspose.BarCode for .NET** NuGet package (`Aspose.BarCode`)  

These items constitute the minimal baseline for the **barcode generator c#** portion of the tutorial.

## How to fill barcode – set up the project

1. Create a new console project:

   ```bash
   dotnet new console -n BarcodeDemo
   cd BarcodeDemo
   ```

2. Add the Aspose.BarCode package:

   ```bash
   dotnet add package Aspose.BarCode
   ```

3. Open the generated `Program.cs` file and replace its contents with the full example shown later in this article.

The project now contains everything required to **generate postal barcode** images.

## Generate postal barcode with solid bars

The first step is to create a Planet barcode that uses filled (solid) bars. Planet is the symbology used by many postal services for sorting.

```csharp
// Step 1: Define the output folder
string outputFolder = "YOUR_DIRECTORY/";

// Step 2: Create a Planet barcode with the default solid (filled) bars
var planetFilled = new BarcodeGenerator(EncodeTypes.Planet, "123456");

// Step 3: Set the X‑dimension (module width) to 4 pixels for better visibility
planetFilled.Parameters.Barcode.XDimension.Pixels = 4;

// Step 4: Save the barcode image with filled bars as PNG
planetFilled.Save($"{outputFolder}PostalPlanetFilledBars.png", BarCodeImageFormat.Png);
```

**Why these lines matter**

* `EncodeTypes.Planet` tells the generator which symbology to use; Planet is the standard for postal barcodes.  
* `XDimension.Pixels = 4` increases the module width, making the barcode easier to scan and visually clearer when printed.  
* `Save` writes the image to disk in PNG format, a loss‑less format suitable for further processing.

Running this block produces **PostalPlanetFilledBars.png**, an image with solid bars that complies with postal specifications.

## Create empty barcode using Planet symbology

Sometimes a postal system expects the bars to be empty (unfilled) while the spaces remain solid. Switching to that mode requires only one property change.

```csharp
// Step 5: Create another Planet barcode that will use empty (unfilled) bars
var planetEmpty = new BarcodeGenerator(EncodeTypes.Planet, "123456");

// Step 6: Apply the same X‑dimension setting
planetEmpty.Parameters.Barcode.XDimension.Pixels = 4;

// Step 7: Configure the barcode to render empty bars instead of solid ones
planetEmpty.Parameters.Barcode.FilledBars = false;

// Step 8: Save the barcode image with empty bars as PNG
planetEmpty.Save($"{outputFolder}PostalPlanetEmptyBars.png", BarCodeImageFormat.Png);
```

**Why this works**

Setting `FilledBars = false` tells the renderer to invert the visual style: bars become transparent (empty) and the background becomes opaque. This is the exact opposite of the default behavior demonstrated earlier, letting you **create empty barcode** images without changing the encoded data.

## Full, runnable example

Below is the complete program that combines the two sections. Copy it into `Program.cs`, replace `YOUR_DIRECTORY/` with a real folder path, and run `dotnet run`.

```csharp
using Aspose.BarCode.Generation;
using System;

class Program
{
    static void Main()
    {
        // Define where the PNG files will be saved
        string outputFolder = "YOUR_DIRECTORY/";

        // -------------------------------------------------
        // Generate a filled (solid) Planet barcode
        // -------------------------------------------------
        var planetFilled = new BarcodeGenerator(EncodeTypes.Planet, "123456");
        planetFilled.Parameters.Barcode.XDimension.Pixels = 4;
        planetFilled.Save($"{outputFolder}PostalPlanetFilledBars.png", BarCodeImageFormat.Png);

        // -------------------------------------------------
        // Generate an empty (unfilled) Planet barcode
        // -------------------------------------------------
        var planetEmpty = new BarcodeGenerator(EncodeTypes.Planet, "123456");
        planetEmpty.Parameters.Barcode.XDimension.Pixels = 4;
        planetEmpty.Parameters.Barcode.FilledBars = false;
        planetEmpty.Save($"{outputFolder}PostalPlanetEmptyBars.png", BarCodeImageFormat.Png);
    }
}
```

### Expected output

After execution you will find two PNG files in the specified folder:

| File name                     | Visual description |
|-------------------------------|--------------------|
| `PostalPlanetFilledBars.png`  | Bars are solid black on a white background |
| `PostalPlanetEmptyBars.png`   | Bars are transparent (white) on a black background |

Both images encode the same numeric string `"123456"` and share the same X‑dimension, ensuring they are interchangeable from a data‑validation perspective.

## Common questions and edge cases

**What if the output folder does not exist?**  
The `Save` method throws a `DirectoryNotFoundException`. Create the folder beforehand or wrap the calls in a `try / catch` block that creates the directory if necessary:

```csharp
if (!System.IO.Directory.Exists(outputFolder))
    System.IO.Directory.CreateDirectory(outputFolder);
```

**Can I use a different image format?**  
Yes. Replace `BarCodeImageFormat.Png` with `BarCodeImageFormat.Jpeg`, `BarCodeImageFormat.Bmp`, or any format supported by Aspose.BarCode.

**Does X‑dimension affect scanner readability?**  
Increasing the pixel width makes the bars wider, which can improve readability on low‑resolution scanners. However, very large values may exceed the printable area. Typical values range from 2 to 6 pixels for 300 dpi printing.

**Is the `EncodeTypes.Planet` symbology the only postal option?**  
No. Aspose.BarCode also supports `EncodeTypes.Postnet` and `EncodeTypes.USPSIntelligentMail`. The same `FilledBars` property works with those types as well.
