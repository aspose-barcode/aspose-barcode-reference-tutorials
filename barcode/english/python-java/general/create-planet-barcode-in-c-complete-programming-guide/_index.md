# Create planet barcode in C# – complete programming guide

If you need to **create planet barcode** in C#, this guide shows you exactly how to do it. You’ll also discover **how to set barcode dimensions** so the bars render at the exact width you require.

Generating Planet barcodes is common when you work with postal services or logistics systems. The code below covers both the default filled‑bar version and the optional empty‑bar style, plus a quick example for the RM4SCC format. By the end of this tutorial you will have a reusable snippet that you can drop into any .NET project.

## Prerequisites

Before you start, make sure you have:

* .NET 6.0 or later installed (the API works with .NET Framework 4.6+ as well)
* The **Aspose.BarCode for .NET** NuGet package (`Aspose.BarCode`) added to your project
* A writable folder path where the PNG files will be saved
* Basic familiarity with C# syntax and Visual Studio (or any IDE)

> **Pro tip:** Use an absolute path or `Path.Combine(Environment.CurrentDirectory, "output")` to avoid permission issues when saving images.

## Step 1 – Initialize a Planet barcode generator (filled bars)

The first step is to create a `BarcodeGenerator` instance for the Planet symbology. By default the generator produces **filled** bars.

```csharp
// Step 1: Create a Planet barcode with the default (filled) bars
BarcodeGenerator planetFilled = new BarcodeGenerator(EncodeTypes.Planet, "123456");
```

The `EncodeTypes.Planet` enum tells Aspose.BarCode to use the Planet format, while `"123456"` is the data payload that will be encoded.

## Step 2 – How to set barcode dimensions for consistent sizing

To control the width of each bar, adjust the **X‑dimension**. This is the primary way to **set barcode dimensions** and ensures the barcode fits your label size.

```csharp
// Step 2: Set the X‑dimension (width of each bar) to 4 pixels
planetFilled.Parameters.Barcode.XDimension.Pixels = 4;
```

The `Pixels` property defines the bar width in screen pixels. Common values are 2 – 5 pixels for standard mailing labels; increase the value for larger prints.

## Step 3 – Save the filled Planet barcode as PNG

Now write the image to disk. PNG preserves crisp edges, which is ideal for scanning.

```csharp
// Step 3: Save the Planet barcode as a PNG image
planetFilled.Save("YOUR_DIRECTORY/PostalPlanetFilledBars.png", BarCodeImageFormat.Png);
```

Replace `YOUR_DIRECTORY` with the path you prepared earlier. After running this code you’ll see a file similar to the image below.

## Step 4 – Create a Planet barcode with empty (unfilled) bars

If your postal service requires the bars to be **empty**, you need to toggle the `FilledBars` flag after initializing the generator.

```csharp
// Step 4: Create a Planet barcode with empty (unfilled) bars
BarcodeGenerator planetEmpty = new BarcodeGenerator(EncodeTypes.Planet, "123456");
```

The constructor is identical; the difference lies in the next configuration step.

## Step 5 – How to set barcode dimensions and make bars empty

Again, set the X‑dimension for visual consistency, then disable filled bars.

```csharp
// Step 5: Set the X‑dimension and specify that bars should be empty
planetEmpty.Parameters.Barcode.XDimension.Pixels = 4;
planetEmpty.Parameters.Barcode.FilledBars = false;   // makes bars empty
```

The `FilledBars = false` property is what actually changes the rendering style. Keeping the same X‑dimension ensures the empty‑bar barcode aligns perfectly with the filled version.

## Step 6 – Save the empty Planet barcode

```csharp
// Step 6: Save the Planet barcode with empty bars as a PNG image
planetEmpty.Save("YOUR_DIRECTORY/PostalPlanetEmptyBars.png", BarCodeImageFormat.Png);
```

You’ll now have two PNG files: one with solid bars and one with hollow bars, both sharing the same dimensions.

## Step 7 – (Optional) Generate an RM4SCC barcode for comparison

RM4SCC is another postal symbology that uses the same default filled‑bar style. The steps mirror the Planet example, demonstrating that **how to set barcode dimensions** works across formats.

```csharp
// Step 7: Create an RM4SCC barcode (filled bars are the default)
BarcodeGenerator rm4scc = new BarcodeGenerator(EncodeTypes.RM4SCC, "123456");

// Step 8: Set the X‑dimension for consistency
rm4scc.Parameters.Barcode.XDimension.Pixels = 4;

// Step 9: Save the RM4SCC barcode as a PNG image
rm4scc.Save("YOUR_DIRECTORY/PostalRM4SCCFilledBars.png", BarCodeImageFormat.Png);
```

Running these three steps produces `PostalRM4SCCFilledBars.png`, which you can compare side‑by‑side with the Planet outputs.

## Why X‑dimension matters

The X‑dimension determines the **minimum printable width** of each bar. If you set it too low, the barcode may blur on low‑resolution printers, causing scan failures. Conversely, a too‑large X‑dimension can exceed label dimensions and waste space. By explicitly **how to set barcode dimensions**, you gain deterministic control over the final image size, which is essential for automated mailing workflows.

## Common pitfalls and how to avoid them

| Issue | Cause | Fix |
|-------|-------|-----|
| Barcode appears stretched | X‑dimension set in points instead of pixels | Always use `Pixels` property for pixel‑perfect control |
| Empty bars still look filled | `FilledBars` not set to `false` after X‑dimension change | Set `FilledBars = false` *after* adjusting X‑dimension |
| Saved file is blank | Output directory does not exist or lacks write permission | Ensure the directory exists (`Directory.CreateDirectory`) and your app runs with sufficient rights |
| Image is blurry on print | Low DPI PNG saved from a high‑resolution monitor | Use `BarCodeImageFormat.Png` (lossless) and consider `Resolution` property if needed |

## Full, runnable example

Copy the entire block below into a new console project (`dotnet new console`) and run it. The program creates three PNG files in the `output` folder.

```csharp
using System;
using System.IO;
using Aspose.BarCode;
using Aspose.BarCode.Generation;

class Program
{
    static void Main()
    {
        // Ensure output folder exists
        string outDir = Path.Combine(Environment.CurrentDirectory, "output");
        Directory.CreateDirectory(outDir);

        // ---------- Planet barcode – filled bars ----------
        BarcodeGenerator planetFilled = new BarcodeGenerator(EncodeTypes.Planet, "123456");
        planetFilled.Parameters.Barcode.XDimension.Pixels = 4; // set dimensions
        planetFilled.Save(Path.Combine(outDir, "PostalPlanetFilledBars.png"), BarCodeImageFormat.Png);

        // ---------- Planet barcode – empty bars ----------
        BarcodeGenerator planetEmpty = new BarcodeGenerator(EncodeTypes.Planet, "123456");
        planetEmpty.Parameters.Barcode.XDimension.Pixels = 4; // same dimensions
        planetEmpty.Parameters.Barcode.FilledBars = false;    // make bars empty
        planetEmpty.Save(Path.Combine(outDir, "PostalPlanetEmptyBars.png"), BarCodeImageFormat.Png);

        // ---------- RM4SCC barcode (filled bars) ----------
        BarcodeGenerator rm4scc = new BarcodeGenerator(EncodeTypes.RM4SCC, "123456");
        rm4scc.Parameters.Barcode.XDimension.Pixels = 4; // consistent size
        rm4scc.Save(Path.Combine(outDir, "PostalRM4SCCFilledBars.png"), BarCodeImageFormat.Png);

        Console.WriteLine($"Barcodes generated in: {outDir}");
    }
}
```

**Expected output:** three PNG files—`PostalPlanetFilledBars.png`, `PostalPlanetEmptyBars.png`, and `PostalRM4SCCFilledBars.png`—each 4‑pixel wide bars, ready for printing or further processing.
